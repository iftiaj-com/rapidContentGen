# The framework

Source: the user's notes on the Modern Story Arc, given in chat on 2026-10-12. The notes do not name
an author, so none is given here. This file restates them in plain words and says how each part is
used in rcg. Nothing here was measured by this project: the intensity numbers and intervals are the
framework's rules of thumb. Treat them as starting points and check them against the job's real
timings.

## Modern arc vs the classic arc

| | Classic five acts | Modern arc |
|---|---|---|
| Shape | setup, rising action, climax, falling action, resolution | start high, quick peak, stacked mini-peaks, end |
| Build | slow | fast |
| Climax | one, near the end | many, every 10-15 s |
| Opening | from zero, with context | at about 70/100, mid-story |
| Risk on a feed | viewers leave during the setup | viewers tire if every beat is a peak (so the releases matter) |

## The five steps

1. **Start at 70/100, the drop-in hook (0-5 s).** Open as if the story is already underway:
   mid-conflict, mid-reveal or mid-statement. The notes' example: instead of "Today I'm going to
   talk about...", open with "Your videos fail because of this one mistake."
2. **First peak at 90/100 (5-15 s).** A "wait, what?" moment: a contrast, a contrarian take or a
   surprising fact.
3. **Release.** Explain, give context, let the tension drop. The notes say 20-30 s, but also say to
   re-peak every 10-15 s. Both fit only in longer videos. **rcg reading:** in videos of 60 s or
   less, keep each release to 10 s or less; use the long release only after the first peak of a
   video over about 90 s.
4. **Stack mini-peaks every 10-15 s.** Peak, release, peak, release. Each peak is a new hook: a new
   insight, a twist, a surprising fact, a strong visual or a bold statement.
5. **Keep re-hooking to the end.** The climax is the chain of peaks that carries the viewer to the
   takeaway or call to action.

Pro tip from the notes: map where each peak lands on the timeline before writing. A 15 s stretch with
no peak gets cut or gets a hook.

## The eight principles

1. **Start at 70.** Drop the viewer into the middle.
2. **First peak at 90** within 5-10 s of the hook: contrast, contrarian take or a striking fact.
3. **Release to about 30.** Let tension breathe.
4. **Re-peak every 10-15 s.** Many small climaxes, not one.
5. **"But" and "therefore", not "and then".** "But" makes conflict, "therefore" makes
   consequence; "and then" is a list. This rule is widely credited to Trey Parker and Matt Stone
   (the South Park creators), who described it to a film class in a clip that is often shared. The
   user's notes do not name them; the attribution is ours and general, not a quote.
6. **Keep the brain off-balance.** A misdirection every 2-3 minutes. **rcg reading:** most rcg
   videos run under 90 s, so use one misdirection at most, near the two-thirds mark, usually as a
   twist peak.
7. **One core idea per video.** One takeaway, then out.
8. **Write the ending first.** The notes call the final line the "last dab". Write it first, then
   build backwards so the ending feels inevitable.

**The core formula: expectation vs reality.** When reality beats what the viewer expected, they
stay. When the expectation beats reality (the hook promised more than the video gave), they leave.
The notes call the whole system "prediction cycle architecture": keep the brain guessing so it does
not get bored.

## The eight social media truths, and what each means for a script

The notes list these as beliefs about social media. Some are channel strategy rather than script
craft. They are opinions from the framework, not findings this project checked.

| Belief in the notes | What the script writer does with it |
|---|---|
| 1. Virality can be engineered: define an ideal viewer and make content for them | Write the **Viewer** line of the brief first and write every line to that one person. Do not promise the user reach. |
| 2. Ideas are everything: a great idea beats a great edit | Spend effort on the core idea and the expectation-vs-reality gap before polishing lines. If the idea is weak, say so to the user. |
| 3. Storytelling is a cheat code: people click for the hook, stay for the story | Name a clear goal or question early (the open loop) and use tension-and-release waves. |
| 4. Focus on the visual hook: the first 5-30 s decide everything | Write three hook options and pair the chosen one with a frame-1 visual. The hook is worth the most rewriting time. |
| 5. Editing is not everything: information and relatability beat polish | Prefer a concrete, relatable detail over a clever phrase. The script carries the video. |
| 6. Science over art: storytelling is a formula | Use the checklist in `SKILL.md` every time. Do not rely on instinct alone. |
| 7. Specificity always wins | Name the exact viewer, the exact mistake, the exact thing. Cut vague words ("things", "stuff", "a lot"). |
| 8. You only lose if you stop posting | Out of scope for one script. When a job is a series, keep the peak maps so later scripts can learn from what worked. |

## Where rcg overrides the notes

- **Shocking stats:** allowed only when sourced this session (organization rules). Otherwise use
  another peak device.
- **Intensity numbers:** a planning score for comparing beats, never shown to the user as data.
- **Release length and misdirection interval:** scaled down for short videos (above).
- **Tone:** the style skill's voice (diary, essay, promo) comes first; the arc fits inside it.
